# RFP Multi-Agent Proposal Generator Architecture

## Objective

This system automates Request for Proposal analysis and proposal generation. It replaces a manual workflow where a human reads an RFP, extracts requirements, estimates scope, calculates effort, prepares a timeline, identifies risks and drafts a proposal.

The application uses a hierarchical multi-agent workflow led by a CEO Agent. Gemini AI performs the initial RFP intelligence extraction, and specialist agents convert that intelligence into a complete proposal.

## Inputs

- Open-source RFP documents in PDF, DOCX or TXT format.
- The project includes sample RFPs under `RFPs/` and `data/rfps/`.
- The upload API accepts one RFP file per proposal generation request.

## Outputs

The generated proposal includes:

- Executive summary
- Client understanding
- Proposed solution
- Technical architecture
- Resource plan
- FTE count
- Estimated person-month effort
- Estimated project hours
- Project timeline and completion deadline
- Cost breakdown
- Risk assessment
- Compliance matrix
- User stories
- ROI and POC comparison
- Markdown export
- PDF export

## Event Flow

1. User uploads an RFP in the Next.js UI.
2. `app/api/proposals/route.ts` receives the uploaded file.
3. `extractTextFromFile()` in `lib/document/extractor.ts` extracts text from PDF, DOCX or TXT.
4. `analyzeRfpWithAI()` in `lib/document/rfp-analyser.ts` sends the RFP text to Gemini.
5. Gemini returns structured RFP intelligence.
6. The AI output is normalized into the internal `RfpAnalysis` schema.
7. `ProposalOrchestrator.run()` starts the CEO-led workflow.
8. CEO Agent defines strategy and delegation order.
9. Product Manager Agent converts requirements into features, epics, user stories and milestones.
10. CTO Agent maps technical architecture, stack, integrations and risks.
11. Resource Planning Agent calculates team composition, FTEs, person-months and estimated hours.
12. Cost Estimation Agent calculates development, infrastructure, licensing, contingency, support and total cost.
13. Timeline Agent calculates delivery phases, duration and estimated completion date.
14. Risk Agent evaluates technical, delivery, budget and compliance risks.
15. Agents perform a review/debate cycle and revise assumptions where needed.
16. CEO Agent consolidates outputs through `buildProposal()`.
17. `renderMarkdown()` and `renderPdf()` generate downloadable artifacts.
18. The frontend replays the workflow as a live event stream.

## Agent Hierarchy

### CEO Agent

The CEO Agent is the master agent. It starts the workflow, delegates work, coordinates review findings, resolves conflicts and consolidates the final proposal.

### Product Manager Agent

The Product Manager Agent converts AI-extracted requirements into product features, epics, user stories, deliverables, milestones, roadmap items and success criteria.

### CTO Agent

The CTO Agent creates the architecture plan. It selects technology direction, integration strategy, security architecture, deployment approach, scalability strategy and technical risks based on RFP scope.

### Resource Planning Agent

The Resource Planning Agent calculates staffing. It produces team composition, total FTE, effort in person-months and estimated project hours.

### Cost Estimation Agent

The Cost Estimation Agent converts effort and complexity into budget. It calculates development cost, infrastructure cost, licensing cost, contingency, support and total budget.

### Timeline Agent

The Timeline Agent calculates delivery phases, phase durations, milestones, total duration and estimated completion date.

### Risk Agent

The Risk Agent identifies technical, delivery, budget and compliance risks and produces mitigations.

## Calculations

### FTE

FTE is calculated from the team composition generated by the Resource Planning Agent:

```text
totalFte = sum(role.fte)
```

### Person-Month Effort

```text
effortPersonMonths = sum(role.fte * role.months)
```

### Estimated Hours

```text
estimatedHours = effortPersonMonths * 160
```

The system uses 160 hours as the standard monthly working-hour assumption.

### Cost

The Cost Estimation Agent chooses a monthly rate based on project complexity:

```text
High complexity:   18,000 USD / person-month
Medium complexity: 14,000 USD / person-month
Low complexity:    10,000 USD / person-month
```

It then calculates:

```text
developmentCost = effortPersonMonths * rate
infrastructureCost = max(domain minimum, developmentCost percentage)
licensingCost = max(domain minimum, developmentCost percentage)
contingencyCost = developmentCost * contingency percentage
supportCost = developmentCost * support percentage
totalBudget = developmentCost + infrastructureCost + licensingCost + contingencyCost + supportCost
```

### Completion Deadline

The Timeline Agent estimates total duration in weeks from AI-derived complexity, domain and integration signals. The estimated completion date is calculated by adding the duration to the current date.

### ROI and POC Comparison

The ROI module compares the automated workflow against a manual RFP analysis baseline:

```text
manualEffortHours = 48 * requirementFactor
automatedEffortHours = estimated system processing effort
timeSavedHours = manualEffortHours - automatedEffortHours
efficiencyGainPercent = timeSavedHours / manualEffortHours
```

This acts as the proof-of-concept measurement for reduced manual effort.

## Hallucination Controls

The system uses several safeguards:

- Gemini prompt requires exact JSON schema.
- Gemini prompt instructs the model not to invent budgets, deadlines, dates, quantities or legal constraints.
- Missing budgets and deadlines are marked as not specified.
- AI output is normalized before agents receive it.
- Agents use calculated costs and deadlines rather than free-form AI budget guesses.
- Consistency checks validate timeline, budget, staffing and risk outputs.
- A review/debate cycle allows specialist agents to flag conflicts.

## Why This Is Hierarchical

The system is hierarchical because the CEO Agent controls the workflow and delegates to specialist agents. The specialist agents do not independently decide the full workflow; they operate within the CEO-directed sequence and return structured outputs for review and consolidation.

## Why This Is Multi-Agentic

The system is multi-agentic because separate autonomous agent classes own different reasoning responsibilities:

- Strategy
- Product scope
- Technical architecture
- Resource estimation
- Cost estimation
- Timeline planning
- Risk analysis

The agents exchange messages through workflow memory, review each other's outputs and produce a consolidated final proposal.
